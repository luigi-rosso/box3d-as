## Task plumbing

Kept as an abstraction for the jobs phase. `b3World` gained the four C fields
decls.md listed as skipped: `enqueueTaskFcn: b3EnqueueTaskCallback`,
`finishTaskFcn: b3FinishTaskCallback`, `userTaskContext: u64`, `userTreeTask:
u64` (0 is C's NULL). The defaults are C's `b3DefaultAddTaskFcn` (runs the task
inline, returns 0) and `b3DefaultFinishTaskFcn`. The task closure carries C's
`void* taskContext`, so callers pass 0 for it. `b3CreateWorld` installs an
external task system exactly as C when `workerCount > 0` and both callbacks are
set; otherwise it takes C's serial fallback (workerCount 1). C's built-in
scheduler branch (`workerCount > 1` without callbacks) also lands on the serial
fallback: the scheduler is skipped.

`b3ParallelFor` keeps C's shape: shared block counter, per worker
`b3ParallelForTask`, enqueue up to `taskCount` trampolines, finish the non-null
handles. broad_phase.as already enqueues its tree task through
`world.enqueueTaskFcn` and `userTreeTask`; solver.c's split island and solver
tasks can do the same.

## Signatures that differ from C

- Pointer returning lookups: `b3GetUnlockedWorldFromId(id): b3World?` and
  `b3GetUnlockedWorld(index): b3World?` (null where C returns NULL);
  `b3GetWorldFromId`, `b3GetWorld` return `b3World`.
- Hull database functions take and return `b3HullData` references.
- Queries drop `void* context` (closures): `b3World_OverlapAABB(worldId, aabb,
  filter, fcn)`, `b3World_OverlapShape(worldId, origin, proxy: b3ShapeProxy,
  filter, fcn)`, `b3World_CollideMover(worldId, origin, mover: b3Capsule, filter,
  fcn)`, `b3World_CastRay(worldId, origin, translation, filter, fcn)`,
  `b3World_CastShape(worldId, origin, proxy, translation, filter, fcn)`,
  `b3World_CastMover(worldId, origin, mover: b3Capsule, translation, filter, fcn:
  b3MoverFilterFcn?)`, `b3World_SetCustomFilterCallback(worldId, fcn?)`,
  `b3World_SetPreSolveCallback(worldId, fcn?)`.
- `b3World_Explode(worldId, def: b3ExplosionDef)` takes the struct by value.
- `b3World_SetUserData(worldId, u64)` / `b3World_GetUserData(): u64`.
- `b3ParallelFor(world, callback, itemCount, minRange, name)`.
- `b3SolvePlanes(targetDelta, planes: StaticArray<b3CollisionPlane>, count)`,
  `b3ClipVector(vector, planes: StaticArray<b3CollisionPlane>, count)`.
- Name cache: `b3NameCache` is `Map<u32, string>` (decls.md), with
  `b3CreateNameCache()`, `b3DestroyNameCache(cache)`, `b3AddName(cache, name:
  string): u32`, `b3FindName(cache, id): string?`, `b3FindNameWithDefault(cache,
  id, def)`, `b3Hash32(data: Uint8Array, length)`. An empty string is C's NULL
  or empty name. The id is `b3Hash32` of the name's UTF-8 bytes, so ids match C
  (verified). `b3LoadName` is skipped (recording and snapshots).
- Event getters return the event classes of types.as holding the world's
  arrays (the double buffered end events use the previous buffer, as C).

## Deviations

- `world.hullDatabase` is the `b3HullMap` of hull.as (C's type, lookup by hash
  then content via `b3CompareHullData`), not the `b3HullDatabase` class
  decls.md declared. One map implementation instead of two; hull.as owns it
  because compound baking uses it too. The `b3HullDatabase` and
  `b3HullDatabaseEntry` classes are removed from physics_world.as.
- `world.names` is typed `b3NameCache` (the same `Map<u32, string>`).
- `b3CreateWorld` replaces the slot with `new b3World()` (C's memset), keeping
  the generation; the fresh object already holds every empty container C
  creates or reserves, so the reserves and the hull map and name cache
  creation calls are gone. `b3DestroyWorld` still runs
  `b3DestroyShapeAllocations` on every live shape (it releases the hull
  references the empty database assert checks), then replaces the slot with a
  fresh object at generation + 1, which drops every container C frees one by
  one (worker contexts, events, sensors, islands, solver sets, graph,
  broad-phase, id pools).
- `b3ResolveContactBodySim` returns a copy of the sim (the collide task only
  reads it). Perf note: the copy is a 63 leaf multi-value return per contact
  side; binaryen should trim it, or bind the set array and index instead.
- `b3PrefetchContact` is dropped (no prefetch in wasm).
- `WorldMoverContext` owns the 64 element plane buffer, allocated once per
  `b3World_CollideMover`, where C uses a stack buffer per shape. The user gets
  the same buffer every call in both.
- Query contexts are small classes; the tree callbacks are closures over them.
  `b3World_CastRayClosest` holds its `b3RayResult` in a class so the closest
  hit callback can write it through a `ref`.
- `b3ShapeCastCallback` and `MoverCastCallback` copy the context's
  `b3ShapeCastInput` (a class) per shape, as C copies the struct; the proxy
  points alias, as C's pointer does.
- `b3World_CastMover` points the proxy at a two element array holding
  `center1` and `center2` (C points at the adjacent fields).
- `b3World_GetCounters`: `stackUsed`, `byteCount` and `arenaCapacity` read 0
  (no stack, arena or block allocator, notes/containers.md).
  `b3World_DumpMemoryStats` does nothing: the byte count walk
  (`b3GetWorldByteCount`) is not ported.
- `b3_worlds` holds 128 `b3World` objects from module start, as C's static
  array. Each is a full object graph (graph colors, trees, arrays); if startup
  memory matters, empty slots could share a lighter placeholder.
- `B3_MAX_WORLDS` overflow logs through `b3Log` with string concatenation.

- `b3LoadName` (recording, snapshots).

## lib/box3d.as

`verify/exports.py` reads the public headers (`base.h`, `id.h`, `constants.h`,
`math_functions.h`, `collision.h`, `types.h`, `box3d.h`: box3d.h includes base.h
and id.h, so they are part of the one module an app imports), collects every
`B3_API`, `B3_INLINE`, `B3_FORCE_INLINE` and `B3_ID_INLINE` function, typedef,
enumerator, define and static const, finds the lib module that defines each,
and with `--write` regenerates `lib/box3d.as` as one `export { ... } from`
block per module. Without `--write` it reports what is missing and exits 1.
Debug draw, recording and replay, file IO and compiler plumbing are skipped
by pattern.

At the last run: 926 names from 29 modules; not exported because no module
defines it yet: `b3ValidateCompound` (compound.c, ported later). Rerun
`verify/exports.py --write` once the remaining modules land.

## Verification

| check | status |
|---|---|
| `verify/run.sh mover` | 16000 lines, 112096 values, 0 mismatches, with and without `-O`. 8000 random plane sets of 0 to 8 planes (rigid, zero and soft push limits, clip flags), at length units 1, 0.37 and 100; clip with solved pushes and with signed zero pushes. |
| `verify/run.sh names` | 6867 lines, 0 mismatches. `b3Hash32` over 3000 random names mixing ASCII and 2 and 3 byte UTF-8, add, find, re-add, finds of known and random ids. |

`world` (`verify/cref/world.c`, `verify/as/world.as`, `verify/world.mjs`) goes
through `lib/box3d.as` only:

- registry: create two worlds, destroy and recreate one (slot and generation
  reuse), invalid ids, world counts; every setter with clamping inputs and
  every getter; bounds of an empty world; destroy.
- a scene: ground hull, a 5 box stack with a revolute joint and joint event
  thresholds, 4 spheres with hit events and initial velocities, 3 rotated
  capsules, a kinematic box sweeping through them, a bullet sphere at 60 m/s,
  a sensor; a custom friction callback, removed at step 60.
- 160 steps of 1/60 with 4 sub-steps, with an explosion at step 40, gravity
  change and body destruction at 60, a new body at 80 (id reuse), contact
  tuning and warm starting off at 100; then a zero time step. After every
  step: every body (valid flag, position, rotation, velocities, awake), the
  counters (except the allocator ones), max capacity, contact begin, end and
  hit events, sensor events, body move events, joint event count.
- every 20 steps: `OverlapAABB` and `OverlapShape` (each callback's shape id
  and the tree stats), `CastRay` with a closest, an all hits and a skip first
  callback, `CastRayClosest`, `CastShape` with a box proxy, `CastMover` with
  and without a filter, `CollideMover` (every plane) fed into `b3SolvePlanes`
  and `b3ClipVector`, `GetBounds`.

The C side runs: 3787 lines, with 21 begin, 7 end, 4 hit, 4 sensor events, 83
cast and 84 overlap callbacks, 24 plane results. The node runner collects
between steps, so the world is moved by the collector mid run.

Self review, done once against C for every function: struct elements written
through places (`set.bodyStates[i].linearVelocity`, `color.contacts[i]
.manifoldCount`, `ref` into the contact's manifold StaticArray and its points);
the explosion re-reads `world.bodies[bodyId]` after `b3WakeBody`, where C
re-reads `body->setIndex`; `context.h` divides by `<f32>subStepCount`; the
contact state loop reads `bitSet.blockCount` each iteration as C; no f64
literals leak.

## Hazards found

- decls.md's per file note for the world says "No scheduler: where C calls
  `enqueueTaskFcn`, call the task inline". The task fields now exist, so
  porters can keep C's enqueue/finish calls verbatim; either way runs inline.
- `b3WorldDef.workerCount` is `u32` in types.as where C has `int`;
  `b3CreateWorld` casts it.
- `verify/as/decls.as` (not mine, run by hand) still builds `b3HullDatabase`
  and `b3HullDatabaseEntry`, which this port removed; drop those lines.
- `B3_ASSERT` arguments are still evaluated under `-O` (notes/types.md); the
  world asserts are on cold paths, the collide task's two are cheap reads.

## rasc findings

No compiler or std changes. Confirmed working, relied on here:

- `export { a, b as c } from "./m"` re-exports, including struct names used as
  constructors by importers (`b3Vec3(...)` through lib/box3d.as).
- `type b3NameCache = Map<u32, string>` as an alias of a generic class.
- A nullable return (`b3World?`) narrows after `if (world == null) return;`.
- A struct module global (`let b3_worldCount = b3AtomicInt();`) with field
  writes.
- Closures capturing a parameter (`context`) or a `const` local per loop
  iteration, passed as function typed parameters, with struct parameters
  (`b3ShapeId`, `b3Vec3`, `b3RayCastInput`).

One limit met: a union type is refused with "union types are not supported;
write T? for a nullable type" (`string | null`), as notes/types.md says.
